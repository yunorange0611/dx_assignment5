# 底盘功率限制调参说明

> 适用：工程车底盘，裁判规则 50W / 500J。
> 对应固件：`build/Debug/dx_assignment5_freertos.elf`（三份 FM 工程同一份 ELF）。
> 当前 `ChassisPowerConfig.confirmed = false`：功率环代码已就绪，但默认不参与控制；独立底盘仍只受 `ChassisConfig.max_current_ma` 和速度斜坡约束。
> 本文只讲功率环相关变量和流程；底盘基础调参仍以 `00_分批调参步骤.pdf` 为准。

## 1. 规则要点

- 裁判以 1000Hz 检测底盘功率 `P_r`，上限 `P_l = 50W`，缓冲能量上限 `Q = 500J`。
- 每 1ms：
  ```text
  Z = Z - (P_r - 50W) × 0.001
  ```
  即每超出 1W、持续 1 秒，消耗 1J 缓冲。
- 未超限时缓冲回充；`Z` 不会超过 500J，最低 -10J。
- **`Z ≤ 0` 才切断底盘电源 5 秒**，5 秒后恢复；不是瞬时超过 50W 就断电。
- 因此过坎、过减速带的短时大扭矩可以接受，关键是**不要把 500J 缓冲耗光**。
- 底盘功率只统计产生水平平移/旋转的动力系统；特殊任务、抬升机构、攀登台阶/跨越障碍等功能性动作按规则可能不计入，但“以组委会判断为准”，未确认前不要依赖。

## 2. 控制结构

功率环采用**功率 → 速度**，不是功率 → 电流：

```text
power_filtered_w = 对 power_w 做一阶滤波，时间常数 power_filter_ms
energy_scale     = clamp((energy_j - stop_energy_j) / (warning_energy_j - stop_energy_j), 0, 1)
power_scale      = power_filtered_w > budget_w ? budget_w / power_filtered_w : 1
speed_scale      = min(energy_scale, power_scale)

speed_request *= speed_scale
turn_request  *= speed_scale
```

- 滤波功率超预算时，降低的是**目标速度**，不是驱动电流；坡道和坎的扭矩仍由轮速 PI 和电流上限提供。
- `drive_scale` 固定为 1；`drive_current_ma` / `braking_current_ma` 只做电机、C620 安全封顶。
- `power_speed_scale`（FM 只读）就是上面的 `speed_scale`：1 = 不限速，<1 = 正在降速。
- 当前独立底盘直驱在 `power_confirmed` 且 `power_stop_requested`/`power_inhibited` 时撤销 `drive_armed`；解锁需重新左拨杆上、右拨杆中、五通道回中300ms，避免功率恢复后沿用旧杆量。

## 3. 参数总表

### 3.1 FM 在线可调（只存 RAM，断电恢复源码默认）

| 参数 | 当前默认 | 含义 | 调整建议 |
|---|---|---|---|
| `tune_chassis_power_budget_w` | 45W | 功率环目标预算。滤波功率超过它，`power_speed_scale` 开始小于 1 | 40 起步 → 45；最高 49，不要贴着 50 |
| `tune_chassis_power_filter_ms` | 300ms | `power_w` 的一阶滤波时间常数。越大越不理会坎/减速带的瞬时 spike，但缓冲消耗更大；越小降速越快 | 过坎掉速太狠 → 500–800；缓冲掉太快 → 200 |

### 3.2 编译期参数（`2User_Driver/Power/chassis_power.h`）

| 参数 | 当前默认 | 含义 | 调整建议 |
|---|---|---|---|
| `confirmed` | false | 功率环总开关。false 时独立底盘路径完全不调用 `limit()` | 平地验证完再改 true 重编 |
| `budget_w` | 45W | 同上，FM 初值 | 同 |
| `power_filter_ms` | 300ms | 同上，FM 初值 | 同 |
| `warning_energy_j` | 300J | 能量比例开始从 1 下降的阈值 | 想更早降速 → 提高；想多用缓冲 → 降低，但必须 > stop |
| `stop_energy_j` | 80J | 低于它进入受控停车；裁判是 Z≤0 才断 5s，80J 是余量 | 想更保守 → 提高；想多用缓冲 → 降低，但别低于安全停车所需 |
| `restart_energy_j` | 350J | 功率锁存后清除所需的缓冲能量；必须 ≥warning 且 ≤500 | 回充慢/比赛紧 → 降低（不能低于 warning）；想更安全 → 提高 |
| `drive_current_ma` | 16000mA | 功率限制器的驱动电流安全上限，每轮；不是功率计算值 | 要保证坡/坎扭矩 → ≥`max_current_ma`；≤20000 |
| `braking_current_ma` | 8000mA | 功率限制器的制动/功率停车电流上限，每轮；启用后正常制动也被它钳 | 下坡/停车弱 → 10000–12000；不能超过 `drive_current_ma` |
| `timeout_ms` | 200ms | 功率计帧超时，超过进 `StopFeedback` | 按帧周期覆盖 2–3 帧；帧周期 100ms 就改 300–500 |
| `stopping_timeout_ms` | 2000ms | 低能量/丢帧后允许受控制动的最大时间，超时锁存 `Inhibited` | 停车距离长 → 加大；太大车可能继续滑 |

### 3.3 相关但属于底盘控制层的参数

| 参数 | 位置 | 当前默认 | 含义 |
|---|---|---|---|
| `max_current_ma` | `2User_Driver/Chassis/chassis_config.h` | 15000mA | 轮速 PI 输出的绝对钳位，也是单轮调参的启动电流上限 |

### 3.4 FM 只读状态

| 变量 | 含义 |
|---|---|
| `g_chassis_status.power_w` | 功率计瞬时底盘总功率，W |
| `g_chassis_status.energy_j` | 裁判缓冲能量 Z，J；开局约 500 |
| `g_chassis_status.min_energy_j` | 本次统计内最低缓冲能量，J；上电或成功清功率锁存/底盘维护清错后重新统计，功率计首帧前显示0 |
| `g_chassis_status.power_over_50_ms` | 原始 `power_w > 50W` 的累计时间，ms；不受滤波影响，丢帧/超时期间不计 |
| `g_chassis_status.power_over_latched` | 本次统计内是否曾出现原始功率 >50W；0/1，只读，不是故障也不会切电 |
| `g_chassis_status.power_filtered_w` | 滤波后功率，和 `budget_w` 比较 |
| `g_chassis_status.power_speed_scale` | 功率/能量综合限速比例 0..1；1=不限速，<1=在降速 |
| `g_chassis_status.power_confirmed` | `confirmed` 是否生效（0/1） |
| `g_chassis_status.power_configuration_valid` | 功率配置数值是否合法 |
| `g_chassis_status.power_phase` | 0 Disabled，1 Ready，2 Driving，3 StopLowEnergy，4 StopFeedback，5 Inhibited |
| `g_chassis_status.power_reason` | 0 None，1 Unconfirmed，2 InvalidConfig，3 NoMeter，4 LowEnergy，5 FeedbackLost，6 StopTimeout，7 Stopped，8 ExternalStop |
| `g_chassis_status.power_session_allowed` | 功率模块是否允许出力 |
| `g_chassis_status.power_stop_requested` | 是否请求受控停车 |
| `g_chassis_status.power_inhibited` | 是否锁存禁行，需要清错 |
| `g_chassis_status.power_frames` / `power_received_ms` | 帧数/最近接收时间，判断在线 |
| `g_chassis_status.current_ma[0/1]` | 最终提交电流，mA；看功率环有没有砍扭矩 |

**注意**：`confirmed=false` 时 `power_speed_scale` 显示 0、`power_session_allowed=0`，但独立底盘路径不会乘它，也不会被它拦；这是“功率模块未启用”的状态，不是真的限速。

### 3.5 只读诊断（不切电）

`power_over_50_ms`、`power_over_latched`、`min_energy_j` 只做观察，**不改变功率环、不请求停车、不切断底盘电源**：

- `power_over_50_ms` 用原始 `power_w` 统计，过坎/减速带的尖峰也会计入；它回答“这次试跑累计超 50W 多久”，不是“是否该断电”。
- `power_over_latched` 只表示本次统计内出现过原始功率 >50W。过坎本来就可能置 1，不能单独作为调参失败的判据。
- `min_energy_j` 回答“这次试跑最低把缓冲用到多少”，比瞬时功率更适合判断是否调得过头。
- 诊断在 `confirmed=false` 时也会更新，可先用来验证功率计；丢帧/超时期间不累计。上电、成功清功率锁存，或写 `g_chassis_debug_request.mode=1` 做底盘维护清错时，诊断清零。
- 裁判的 `Z≤0` 5 秒断电仍由裁判执行，固件没有瞬时 50W 硬切。

## 4. 三个电流参数

| 参数 | 所属层 | 作用 | 当前值 |
|---|---|---|---|
| `max_current_ma` | `ChassisConfig` → `ChassisControl` | 轮速 PI 输出绝对钳位；单轮调参启动上限 | 15000 |
| `drive_current_ma` | `ChassisPowerConfig` → `ChassisPower::limit()` | 功率限制器的驱动电流安全上限 | 16000 |
| `braking_current_ma` | `ChassisPowerConfig` → `ChassisPower::limit()` | 功率限制器的制动/功率停车电流上限 | 8000 |

实际生效关系：

```text
实际驱动电流 = min(PI 输出, max_current_ma, drive_current_ma [confirmed])
实际制动电流 = min(PI 输出, max_current_ma, braking_current_ma [confirmed])
```

- `confirmed=false`：只有 `max_current_ma` 生效，`drive_current_ma` / `braking_current_ma` 不参与。
- `confirmed=true`：正常制动也会被 `braking_current_ma` 钳住；如果它比 `max_current_ma` 低，启用功率环后停车/下坡会变弱。
- 三者都是**每轮** mA，不是两轮总和；C620 量程 ±20000mA。
- 生效的驱动电流取较小的那个：当前 `max_current_ma=15000`、`drive_current_ma=16000`，实际驱动上限是 15000。

## 5. 调参流程

### 5.1 启用前：验证功率计

保持 `confirmed=false`，在 FM「功率限制（当前未启用）」组看：

- `power_frames` 是否持续增长，`power_received_ms` 年龄是否稳定；
- 静止时 `power_w` 是否接近 0；
- 加载时 `power_w` 是否为正、量级合理（可和电压×电流粗对）；
- 开局/上电时 `energy_j` 是否接近 500J；
- 记录 `power_frames` 1 秒增量，算帧周期；`timeout_ms=200` 至少覆盖 2–3 帧，不够就改编译期值；
- `power_configuration_valid` 应为 1。

读数不对，先别启用。

### 5.2 启用

1. 把 `2User_Driver/Power/chassis_power.h` 的 `confirmed` 改成 `true`；
2. 确认 `max_current_ma` 与 `drive_current_ma` 匹配（要 16000 就把 `max_current_ma` 也提到 16000）；
3. `braking_current_ma` 默认 8000；觉得停车弱可以 10000–12000；
4. 重编 Debug/Release，烧录；
5. 关掉旧 FreeMASTER，重新打开新生成的 `底盘调参.pmpx`；
6. 确认 `power_confirmed=1`、`power_phase=Ready/Driving`。

### 5.3 平地

- 低速小目标：`power_filtered_w` 应接近 `power_w`，`power_speed_scale` 应为 1；
- 逐渐加大速度，让 `power_w` 接近 45W：
  - `power_filtered_w` 超过 `budget_w` 后，`power_speed_scale` 开始小于 1；
  - 同时看 `current_ma`：它应由轮速 PI 决定，不应因为功率环被砍；
  - `energy_j` 应稳定或缓慢回充，不应持续下降。
- 调 `tune_chassis_power_budget_w`：先从 40 试，再到 45，最多 49。
- 调 `tune_chassis_power_filter_ms`：
  - 减速带/坎的 spike 会让速度掉得太狠 → 加大到 500–800ms；
  - 缓冲掉得太快、降速太慢 → 减小到 200ms。
- 记录低功率时 `energy_j` 每秒回充多少 J，这决定后面 `warning/stop/restart` 的余量。
- 每次试跑前可写 `g_chassis_debug_request.mode=1` 并最后递增 `request_seq`，清底盘维护状态的同时把诊断清零；跑完重点看 `min_energy_j` 和 `power_over_50_ms`。`power_over_latched=1` 只说明曾有尖峰，不能单独判失败。

### 5.4 10° 长坡

- 低匀速爬，记录稳定 `power_w`、`power_filtered_w`、`power_speed_scale`、`energy_j`；
- 如果稳定功率已经超过 45W，功率环会降速；找一个能保持 `energy_j` 不持续下降的速度；
- 如果降速后仍上不去，是扭矩/抓地问题，不是功率环。

### 5.5 陡坎

- **坎前把 `energy_j` 补到接近 500J**；
- 低速正对坎，不要冲；
- 过坎瞬间看：
  - `power_w` 峰值、`energy_j` 下降量；
  - `power_speed_scale` 不应在坎中间掉到很低（滤波应把它挡住）；
  - `current_ma` 应能到 15000 左右，不被功率环砍；
  - 过坎后看 `min_energy_j` 和 `power_over_50_ms`：尖峰会让 `power_over_latched=1`，这是正常的；关键是最低缓冲有没有接近 `stop_energy_j`；
- 如果坎中速度被砍得太狠，加大 `power_filter_ms`；如果缓冲掉得太快，减小滤波或降低坎前速度。

### 5.6 下坡

- 低目标速度，靠 `braking_current_ma=8000` 制动；
- `power_w` 可能为负，`energy_j` 可能回充，`power_speed_scale` 应为 1；
- 如果溜坡，先加大 `braking_current_ma`（不超过 `drive_current_ma`），再降目标速度；
- 确认下坡不会触发 `StopLowEnergy` / `Inhibited`。

### 5.7 保护与恢复

在平地上主动测一次：

- 拔掉功率计/断帧：应进入 `StopFeedback`，受控停车，然后 `Inhibited`；
- 把缓冲跑到 80J 附近：应进入 `StopLowEnergy`，停车，然后 `Inhibited`；
- 恢复：
  1. 左拨杆回中/下，底盘失能；
  2. 写 `g_chassis_debug_request.mode=1`，最后递增 `request_seq`；
  3. 等 `energy_j ≥ restart_energy_j`（350J）；
  4. 当前独立底盘还需重新左拨杆上、右拨杆中、五通道回中保持300ms，`g_robot_status.independent_armed=1` 后才接受摇杆；正常整车路径则按命令4/回中流程恢复。
- `g_chassis_debug_request.mode=1` 会同时清零 `power_over_50_ms`、`power_over_latched`、`min_energy_j`，方便开始下一轮记录；清错是否成功仍看 `g_chassis_debug_status.result`。
- 比赛时尽量不要触发锁存；功率环的作用就是提前降速，避免到 80J。

### 5.8 固化参数

- `tune_chassis_power_budget_w`、`tune_chassis_power_filter_ms` 只存 RAM，断电回默认；调好后写回 `chassis_power.h` 的 `budget_w` / `power_filter_ms`。
- `warning/stop/restart`、`drive/braking`、`timeout_ms` 也在 `chassis_power.h`；按实测坡/坎的能耗和回充速率定。
- 保留一份 `confirmed=false` 的固件作为备用；比赛用 `confirmed=true` 的版本。
- 最后跑一遍完整路线：坡 → 坎 → 下坡，确认 `power_filtered_w` 平均 <45W、`energy_j` 不持续掉、过坎 `current_ma` 不被砍、下坡能停住。

## 7. 正常判据

- `power_phase=2`（Driving）、`power_stop_requested=0`、`power_inhibited=0`；
- `power_speed_scale` 只在功率/能量超限时 <1；
- `power_filtered_w` 平时 ≤45W；
- `energy_j` 不低于 100J，过坎前接近 500J；跑完看 `min_energy_j`，它是本轮最低点；
- 过坎时 `current_ma` 能到 15000 左右，说明功率环没有砍扭矩；
- 下坡 `energy_j` 回充、`power_w` 可能为负，但 `braking_current_ma` 要能停住；
- `power_over_50_ms` 是累计诊断，不设硬上限；如果每次试跑都很长且 `min_energy_j` 持续走低，就降低 `budget_w` 或加大 `power_filter_ms`。`power_over_latched=1` 本身不代表失败。
