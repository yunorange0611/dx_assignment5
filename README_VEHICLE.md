# 整车安全链与第三批接入

整车保留单个ArmOperator和CAN1五轴owner；CAN2由chassis_task独占。vehicle_state_task约20ms聚合真实状态，未开控也持续发布，默认不使用恒真互锁。ins_task按4ms更新BMI088姿态，上向量仅用于倾覆判断，不当作Yaw相对反馈。

分层与调用关系见 README_ARCHITECTURE.md。`Vehicle/vehicle_state`只做精简输入的纯判断，任务层适配真实快照与发布时限；INS不再直接读取Robot、Arm或Chassis任务。

## 上车前确认入口

| 文件 | 必须实测后填写的内容 |
|---|---|
| Chassis/chassis_config.h | 左右C620 ID、方向、内部齿比、有效轮径轮距、低速PI与电流限幅；hardware_confirmed默认false |
| Arm/yaw_config.h | 电流模式、线束自然中位/安全绝对区间、提前制动余量与可靠减速度；Yaw安全确认默认false |
| Remote/operator_config.cpp | DR16通道/拨杆/方向，mapping_confirmed默认false |
| Arm/arm_config.cpp | 队友四轴硬件和pitch映射，保留默认确认门槛 |
| Imu/attitude_estimator.h | 板到车体安装变换、校准和翻车进入/退出阈值，两个确认默认false |
| Vehicle/vehicle_state.h | 实测可行驶机械臂收拢姿态表，posture_confirmed默认false |
| Power/chassis_power.h | 实测功率帧超时、预算、低能量停车阈值、制动电流与时限，confirmed默认false |

这些确认不是开控开关，不能为了消除报错一次全部改真。对应参数未测时正常整车禁行；受限悬空调参使用同一固件的运行时档位和tune_enable。快速许可始终关闭；精细功率模型、满载性能和快速档留待后续。

## IMU与互锁

SPI1采用原C板模板引脚：PB3/PB4/PA7为SCK/MISO/MOSI，PA4加速度CS、PB0陀螺CS；模式3、分频16。先核对实物/引脚冲突。驱动初始化有界重试，芯片ID/配置回读、数据就绪及sensor_time去重，旧数据不刷新源时戳。失败发布无效，不阻塞遥控。

HAL SPI头/源取自同机旧模板dipan，与当前HAL均为v1.8.5。源码增加一处有限超时饱和减法，防止任务抢占后已过截止时间时尾部等待下溢；保留HAL_MAX_DELAY语义。INS优先级低于电机/遥控owner，实际执行时间、最坏延迟和任务栈余量仍需上板观测。

陀螺bias校准只在整车、机械臂、底盘均失能且快照新鲜时进行。上电需静置；`g_ins_debug_command=1`可请求重新静态校准，拒绝后不会迟到执行。安装与阈值未确认时不会给整车许可。状态用INS_GetStatus读取，调试读g_ins_status，勿直接改快照。

校准许可由整车聚合层发布，期限扣除原快照已消耗的时间。出力owner在尝试使能前立即撤销许可；撤销后的同毫秒或旧失能快照不能重新授权，全部源需在撤销时刻之后重新发布失能状态。INS在采样前后复核许可，未完成的标定窗口跨撤销失效。

互锁检查各任务发布时间和原始传感器接收时间；生产任务停止更新也会被发现。两轮静止只表示新鲜轮速低于阈值持续一段时间，不能检测抱死滑移/坡道外推。正常夹取先在平地人工确认；坡道夹取另行验收。

允许行驶来自已测的pitch/roll收拢表及Yaw区间，快速恒为禁止。Yaw实际/目标/参考超行驶包络时请求停车，不删除包络掩盖越界。许可不是整臂碰撞模型，不能证明末端不会接触基地。

`ChassisStatus.configuration_valid`仅表示轮组参数数值合法；`hardware_confirmed`才表示已完成实物核对。功率侧另外发布`power_configuration_valid`和`power_confirmed`。真实互锁同时检查这些字段，不能因为轮反馈在线就忽略未确认的方向、参数或制动约束。

## 低功率与停车阶段

50W/500J为规则边界；首版预算占位40W，预留缓冲在耗尽前停车，不能把缓冲当无条件超功率许可。功率计断链但轮反馈健康时进入显式有时限的停车阶段，停止推进，保留保守且有上限的制动电流；到静止或时限结束后锁存禁行，恢复数据不续跑。若轮反馈丢失或总线故障，立即取消CAN2旧帧并撤力，不承诺闭环停车。

受控停车期间`power_session_allowed`保持有效，`power_stop_requested`要求零速度并禁止新的推进；此时真实互锁不因停车请求直接触发全局急停。静止确认、停车超时或其他保护撤力后进入锁存禁行。外部关控中断停车会报告`ExternalStop`，不会伪报停车超时。即使功率计在第一个已使能周期就失联，只要此前健康状态已授权该周期，也执行同样的有界制动。

轮速PI的抗饱和依据经过功率限制、安全门控和C620整数换算后，实际提交给CAN队列的两个槽位值。约1.22mA的单个整数分辨率及浮点微余量内允许正常积分，避免整数截断让PI退化成纯P；真正的外部限幅仍按最终值抑制同向积分。队列拒绝即锁存发送故障并清控制状态；队列接收不等于电机已收到，仍需反馈超时和总线异常保护。清故障只清状态，不替代回中和显式重新开控；功率禁行还要求新鲜反馈及达到重启能量阈值才可清除。

限功率、制动电流与再生电源电压有不同物理限制。现实现为保守反馈限幅，不是精细功率模型，不能保证所有瞬态都严格低于规则线。要测正常/限功率预算、低缓冲、数据断链时的停车距离、最低缓冲和电压；达不到应先降速度/增加预留，不能用无限制动豁免掩盖。

零输出不是机械锁止，停车时限到达仍可能滑行。带载前双方确认Yaw及整臂撤力行为。翻车/失联/显式关控沿用统一失能锁存，恢复后回中并显式重新开控。正常待机保持已使能关节，底盘受控停车。

## 关控、清错与重新开控

1. **只停止调参对象**：写 `tune_enable=0`，等反馈静止；其他已使能机械臂继续保持。要换对象再改mode，切档会再次关闭enable并清目标。mode0不代表全局关控。
2. **全局关控**：写 `g_robot_debug_command=1` 或调用 `Robot_StopControl()`；核查Arm全部失能、底盘无输出后排除故障。左拨杆上是Drive、下是Standby，不是关控。
3. **分别清错**：Arm用命令3。CAN2本地维护用 `g_chassis_debug_request.mode=1`，最后递增request_seq；不直接撤Arm保持，不自动开控。功率已确认时须有新鲜数据且能量达到restart_energy_j才清功率锁。只看result不够，还要核查faults/power_inhibited等实际状态。日常出力不再使用这组请求mode2/3。
4. **需要时重校零**：反馈多圈失效后，支撑机构并恢复人工零位，再命令2。mode5/6只校Yaw，其余正常0档针对全部五轴；pitch必须联合校零。校零不会恢复限位确认，按需再次申请在线半幅。
5. **明确恢复**：先enable=0、停稳并回mode0，退出调参后机构先保持；选择正常行驶/夹取，实际停车、回中持续neutral_ms，真实互锁和各配置就绪后写命令4或Robot_RequestControl。健康恢复、回0档或清错都不能自动续跑。调参需重新选mode、确认目标和enable=1。

受限调参模式保留遥控/所选电机/保持关节健康检查。IMU已完成安装与阈值确认后，失效或翻车继续制止调参；功率已确认后继续约束轮调参。未确认情况下的受限测试许可不等于正常整车许可。


## 验证顺序

先无出力核对源时间和保护原因，再悬空逐轮方向/速度，独立Yaw小幅限位，再IMU有效性/翻车门控、真实互锁/模式转换、功率受限制动，最后慢速落地和机械臂协作。逻辑测试/编译结果与实物验收分别记录；软件通过不代表已经慢速落地或完成满载测试。当前逐批步骤见原 `fm调参/00_分批调参步骤.pdf`，排障和抬臂保持分别见同目录01、02。
