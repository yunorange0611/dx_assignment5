# 遥控、运行时调参与底盘接口

> 日常Debug/Release均为五轴整车固件。遥控行驶/夹取/待机保持V2.1；FreeMASTER使用robot_tune_mode选调参对象、tune_enable控制测试开始/停止。详细步骤以fm调参原PDF为准。

整车按《遥控器.docx》V2.1（2026-11-09）实现行驶、夹取、待机及默认失能保护。机械臂与底盘/Yaw共用此固件，不通过换固件选调参对象。单C板只解析一次DR16；CAN1由原arm_task统一闭环，CAN2由chassis_task统一实现差速/轮速PI/制动与保守功率限制。

你已确认每车只用一块 C 板、机械臂不能直接接触基地。机械臂与底盘任务共享模式和互锁，不分别解释同一拨杆。V2.1 不启用云台与底盘跟随，旧的登阶、履带和伸收轮遥控路径已移除。

协作分工：机械臂负责人维护两 pitch、roll、夹爪；底盘/yaw负责人维护两台 M3508 和 GM6020。GM6020 参数在 `2User_Driver`，仍由原 CAN1 任务统一发送；完整交接见 [AGENTS.md](AGENTS.md)。

## 同一固件内选择对象

| robot_tune_mode | 功能 |
|---|---|
| 0 | 正常遥控 |
| 1 / 2 | 左 / 右轮电流测试 |
| 3 / 4 | 左 / 右轮速度PI |
| 5 / 6 | Yaw速度内环 / 位置双环 |

`tune_enable`默认0，切档自动关闭；0停止本次调参对象、其他已使能关节保持，1明确允许测试。每次先0→等实际停稳→切mode→确认目标为0（位置档对齐当前角）→1→写小目标。调参须左拨杆下、右拨杆中、五通道回中；先抬臂则在0档正常夹取，抬起后待机保持再测轮，不自动使能未开控的轴。

回0档不是全局关控。退出调参先关闭enable、停稳再回0，机构继续保持；选择正常运动模式、停稳回中后写命令4明确恢复，防止沿用旧杆量。全局关控使用命令1或Robot_StopControl；左拨杆上为行驶，不能按旧台架操作当作关控。遥控失联、电机离线、输出限制和Yaw软限位始终有效。

先验证无输出、反馈和停止，再低电流确认轮方向，之后速度PI、Yaw内环与双环，最后正常模式联调。逐批的填写、观察和异常处理见 [00_分批调参步骤.pdf](fm调参/00_分批调参步骤.pdf)，抬臂保持见 [02_机械臂抬起与保持.pdf](fm调参/02_机械臂抬起与保持.pdf)。

## 少量调试变量与命令

`g_arm_status`、`g_robot_status`、`g_dr16_status` 是原有三个快照符号。调试器只读取它们；其他任务通过Get接口获取所需快照，底盘控制单独用`Robot_GetChassisCommand()`读取请求。`Robot_GetControlStatus()`保留整车诊断和INS校准状态来源。关节数组下标固定：0 yaw、1 大 pitch、2 小 pitch、3 roll、4 夹爪。

| 先观察的字段 | 用途 |
|---|---|
| `g_dr16_status.frame.channel[0..4]/frame.switches[0..1]` | 解码原始五通道/两拨杆；摇杆约 ±660、回中 0，拨杆上=1/下=2/中=3 |
| `g_robot_status.remote_axis[0..3]` | 当前配置映射后的左Y/左X/右Y/右X，含方向和死区，范围[-1,1]；失能时也刷新 |
| `g_robot_status.remote_switch[0..1]` | 当前配置映射后的左/右拨杆，仍用上=1/中=3/下=2；结合remote_online和帧时间判断是否新鲜 |
| `g_dr16_status.start_calls/service_ms/last_start_result/rx_running` | 接收初始化、维护心跳、最近HAL启动结果及UART/DMA是否运行；无需电机开控 |
| `g_dr16_status.rx_events/rx_bytes/last_size/dma_remaining/last_uart_error` | 区分无线／线路无字节、中断没回调、帧被拒收与UART错误；多帧完整批次18/36/54/72逐帧校验后发布最新帧 |
| `g_robot_status.joint_mask/active/block` | 当前配置、是否已开控、被哪一层阻塞；block 名称见 `OperatorBlock` |
| `g_robot_status.protection_current_reasons/protection_latched_reasons` | 当前关控原因与锁存原因 |
| `g_arm_status.faults/enabled_mask/last_result` | 故障、实际使能轴、最近核心操作结果 |
| `g_arm_status.joint[i].online/calibrated` | 仅排查未就绪时展开 |
| `g_arm_status.joint[i].position_deg/target_deg` | 只展开正在调试的轴，看关节反馈和目标 |
| `g_arm_status.joint[i].drive_position_deg/drive_target_deg/effort` | pitch 驱动角换算、跟踪与输出；DM 为 Nm，M2006 为 mA |

通用命令 `g_robot_debug_command` 每轮读取后清0。日常轮/Yaw目标和增益直接用 `tune_*` 输入，由原owner检查，不填旧出力脉冲的wheel/duration/confirm/seq。轮组参数结果看 `g_chassis_tune_status`，Yaw参数结果看 `g_robot_tune_status`。机械臂其他轴仍可使用 `g_arm_tune_request` 受限参数申请，要求全部轴失能、反馈静止健康，最后递增request_seq；这不是运动出力入口。所有在线值只存RAM。

| 写入值 | 执行含义 |
|---|---|
| 0 | 空闲 |
| 1 | 关控 |
| 2 | 0档校零五轴；mode5/6只校Yaw；同周期请求关控 |
| 3 | 清底层故障；同周期请求关控 |
| 4 | 显式请求开控，仍需满足所选配置所有条件 |

命令 2/3 在轴仍使能时由核心拒绝并返回 `Busy=3`，该周期仍关控；应先关控确认失能，再重新发送。它们不隐式开控。校零/清故障结果看 `g_arm_status.last_result`；开控看实际 `enabled_mask/active` 与保护原因，命令清零本身不表示成功。完整结果码在 [README_ARM.md](README_ARM.md)。关控优先于同周期的其他请求。

`fm调参/`提供三个FreeMASTER工程及分批PDF，沿用既有工程的连接配置，不增加FMSTR串口通信栈。打开后加载与已烧固件对应的ELF，再确认`uwTick`和源时间持续更新；本轮文件生成与逻辑验证不代表已完成本机上板连接验证。也可通过原STM32调试器实时变量窗口使用相同入口，不要用断点暂停运动中的控制任务来采样。

## 整车 V2.1 操作映射

| 输入 | 行驶 | 夹取 | 待机 |
|---|---|---|---|
| 左拨杆 | 上档 | 中档 | 下档 |
| 左摇杆上下 | 归一化纵向速度请求 | 肩角 `BigPitch` 目标变化速度 | 不接受新动作 |
| 左摇杆左右 | 独立 yaw 目标变化速度，受行驶包络许可 | roll 目标变化速度 | 不接受新动作 |
| 右摇杆上下 | 不使用 | 肘相对角 `SmallPitch` 目标变化速度 | 不接受新动作 |
| 右摇杆左右 | 底盘角速度请求，不控制 yaw | yaw 目标变化速度 | 不接受新动作 |
| 右拨杆上 | 慢速档 | 张开 | 无动作 |
| 右拨杆中 | 慢速档，默认 | 截断开合目标并限流保持 | 无动作 |
| 右拨杆下 | 请求快速，仍受 `arm_allows_fast` 许可 | 闭合 | 无动作 |

四摇杆经过死区处理。机械臂输入按关节端 deg/s 积分形成角度目标，回中后停止推进目标，不自动回机械零位。底盘请求 `turn_request` 是 [-1,1] 的角速度意图，逆时针为正；右横原码经方向校准后右推为正，输出 `-rx`，即右推令车头顺时针。前进和倒车均保持此约定。

行驶的左横与底盘右横独立，不做Yaw跟随，原恒零字段已移除。行驶时其余机械臂关节不接收摇杆新目标。左右摇杆通道、正向仍需在实物上核对。

两个 pitch 的公共目标是相对于联合校零姿态的肩角和肘相对角。底层换算 `a1=q肩`、`a2=q肩+q肘`，反馈 `q肘=a2-a1`。两关节可同时操作；遥控层共同缩放达到组合限位的增量，底层联合规划参考轨迹并限制第二驱动的叠加速度、加速度。既有换算与夹爪 48 传动比保留。

## 整车模式切换与通用待机策略

进入行驶或夹取、重新获得姿态许可、以及重新开控时，先请求底盘停车；确认 `chassis_stopped` 后，四摇杆和右拨杆须连续回中 300 ms。行驶与夹取双向切换均如此。正常行驶开始后不再持续要求 `chassis_stopped=true`，避免一运动就禁止行驶。

夹取中右拨杆下档不能直接继承为行驶快速档。切入行驶必须先回中，初始为慢速；此后重新拨下才请求快速。快速许可不满足时，诊断中`fast_requested=1`但`drive_gear=SLOW`。当前底盘只有慢速上限，没有独立快速档参数，档位不进入底盘请求；快速请求不会使车变快。

待机是正常模式。进入时只抓取一次当前反馈，经过合法范围约束后作为保持目标；已开控关节继续刷新目标，避免 250 ms 目标看门狗超时。停留待机期间不追随反馈下垂反复重抓目标，也不接收摇杆和右拨杆新动作。原本失能的轴保持失能，待机中的 `Robot_RequestControl()` 被忽略且不会留待退出后执行。

这是候选的位置闭环保持策略，参考轨迹仍按原速度、加速度限制收敛，不能等同于瞬间机械制动或经过验证的承重保持。pitch 暂定 0.3 Nm 上限可能不足以承载；没有重力补偿或抱闸。负载保持策略本轮按用户要求暂不改，后续再实测核定。整车离开待机重新经过停车和回中检查。

## 关控保护

`TaskProtect`沿用默认禁止输出、保护优先与取消旧指令结构；新增真实IMU/翻车、底盘反馈/发送、能量和整车生产者超时原因。未复制旧两板通信或自动恢复，具体时限由当前配置及实测确定。

每 4 ms 控制周期在处理运动输出前汇总保护输入。`Task_Protect_Init()` 默认失能；健康输入只清当前原因，不自动开控。所选配置的回中、反馈、校零等条件就绪后，显式开控请求才尝试解锁；整车另要求真实停车与互锁。开控被拒绝、输出提交失败或底层故障仍会锁存停机；底层控制计算期间发现的故障同周期覆盖共享状态。

| 原因位 | 名称 | 含义 |
|---|---|---|
| bit0 | `PROTECT_BOOT` | 初始等待明确开控 |
| bit1 | `PROTECT_CONFIG` | 硬件、pitch 或遥控映射未确认，或保护输入非法 |
| bit2 | `PROTECT_REMOTE` | DR16 无效或超过 100 ms 未收到有效报文 |
| bit3 | `PROTECT_INTERLOCK` | 整车底盘/安全互锁无效或超过 100 ms 未更新；调参按所选对象的实际健康条件检查 |
| bit4 | `PROTECT_STOP_REQUEST` | 显式关控或 `Arm_Disable()` 请求 |
| bit5 | `PROTECT_TIMING` | 控制周期为 0 或超过当前 4+2 ms 门槛 |
| bit6 | `PROTECT_ARM_FAULT` | 机械臂底层故障、异常失能或目标提交失败 |
| bit7 | `PROTECT_ENABLE_REJECTED` | 条件检查后实际使能仍被拒绝 |

保护触发后使当前配置全部轴失能，清除闭环积分，取消 CAN1 待发旧帧，并持续发送所管理电机的 DJI 零指令和 DM 失能帧。关控优先于同周期开控，恢复通信不会自动使能。待机本身不触发保护失能；负载保持策略本轮暂不改。

该逻辑仍依赖 DR16 接收机失联后停止输出有效报文。必须实测关闭遥控器后 `good_frames` 停止增长；若接收机重复发送合法旧帧，当前无时间戳的 DBUS 报文不能独自辨别。软件超时还包含任务、总线和电机响应时间，并不能代替电机侧通信超时。

整车新版“下方关控”尚未指定物理输入；已有 `Robot_StopControl()` 和遥控失联入口，整车左下仍为待机。左拨杆上是行驶，不能用它代替关控。若整车需要独立按钮关控，仍需明确通道；若指遥控电源，则需验证有效报文停止的实际行为。

`Task_Protect_*` 状态只由机械臂控制任务拥有。其他任务读取 `Robot_GetControlStatus()` 内的保护快照，不并发调用保护状态机；`protection_current_reasons` 表示当前原因，`protection_latched_reasons` 保留历史原因直至明确重新开控。

## 行驶 yaw 包络

底盘/安全管理通过 `Robot_SetInterlocks()` 提供 `drive_yaw_allowed` 以及已核定的最小角、最大角、目标变化速度。角度相对于 yaw 手动校零；范围和速度必须处于全局 yaw 配置内。未提供许可时只禁止行驶中的新 yaw 操作，仍可按其他许可控制底盘。

`drive_yaw_max_speed_deg_s`现在同时限制目标推进、底层参考和内层速度目标；真实角度边界减速和目标领先约束也在原核心中执行。真实转速/停止距离仍依赖电机执行能力，须实测，不能把速度目标限幅当作无限制动能力。

有效包络缩小后，如果 yaw 反馈、目标或参考已经在新范围外，程序请求底盘停车、停止新操作并等待包络/姿态问题处理，再经过停稳回中；不会擅自把机构拉回新边界。撤销 yaw 许可时截断到当前角度，已有参考仍按底层轨迹收敛。该接口限制的是已知关节角和目标推进速度，不是整臂碰撞模型，也不能证明机械臂不会触及基地。

## 夹爪处理

张开、闭合均按配置速度逐步改变 32T 输出轮角目标，运动电流上限暂定 500 mA。右拨杆回中时截断到当时反馈角并以 150 mA 上限保持。连续闭合超过暂定 2 秒后，每周期把目标重置为当时反馈角并降低到 150 mA；不能称为固定角度锁定、接触检测或恒夹持力。改变拨杆档位会重置闭合计时，返回中档后再闭合是推荐操作。

夹爪反馈总比 `36×32/24=48`，后续 32T→32T 只改变转向。张开/闭合暂定 0°/45°，速度 3.75°/s、加速度 11.25°/s²；这些来自旧物理包络的单位换算，未实机整定。用户已确认夹爪没有机械限位，不能撞限位找零；本轮不自动扩大范围。一次两秒闭合最多推进约 7.5°目标，不保证覆盖 45°行程或已经夹紧。需实测零位、闭合方向、可用行程、速度、超时和保持电流。

## 底盘共享接口

底盘通过`Robot_GetChassisCommand()`在同一MCU内取得一次临界区副本，直接复用`ChassisCommand`，不再从整车大快照逐字段转换。历史`ROBOT_CONTROL_API_VERSION=0x0203`仅记录第一批速度字段变更，现已移除，不作为内部通信协议维护。CAN2左轮ID1、右轮ID2已由用户确认。

整车底盘/安全管理约每 20 ms 更新真实互锁状态；100 ms 过期会触发保护。非法布尔值或非法 yaw 包络使互锁立即无效，不继续沿用旧许可。无底盘任务时不能为了开控把全部字段写成 1。

`vehicle_state_task`持续聚合真实Arm、Chassis及INS状态并提供正常整车互锁；不能用调试器一次写值替代。受限调参只放行所选对象的明确条件，不代表整车已获准落地行驶。

| `RobotInterlocks` 字段 | 提供方应保证的含义 |
|---|---|
| `chassis_stopped` | 底盘测量确认停稳，不能仅表示目标速度为 0 |
| `arm_allows_drive` | 机械臂姿态允许行驶 |
| `arm_allows_fast` | 姿态、载荷等条件允许快速；仍要求允许行驶 |
| `drive_yaw_allowed` | 当前姿态允许行驶中操作 yaw |
| `drive_yaw_min_deg/max_deg/max_speed_deg_s` | 当前已核定的 yaw 操作包络；不许可时忽略这些数值 |

| `ChassisCommand` 字段 | 底盘消费规则 |
|---|---|
| `valid/enabled` | 来源已发布与底盘运行许可；正常控制或受限选轮许可由唯一协调方产生 |
| `updated_ms` | 用底盘当前tick检查来源陈旧，不以取用时间刷新 |
| `stop` | 请求受控停车，纵向与转向目标均减速到零 |
| `brake` | 将纵向速度制动到零，允许同时转向 |
| `reset/epoch` | 重置边沿或代号变化时按实测速度重建参考并清积分，避免漏掉短暂模式切换 |
| `speed_request/turn_request` | [-1,1]纵向速度/转向意图，前进与逆时针为正；不是物理速度，倒车不翻转转向符号 |
| `stop_epoch` | 显式停止事件，取消调参运动和CAN2旧帧；与运动重置代号分开 |
| `tune_mode/tune_epoch/tune_value` | 运行时对象、切换代号及受限目标；同一个控制器执行，不增加发送入口 |

整车诊断快照保留模式、关节目标、遥控/互锁年龄、保护原因及快速请求，底盘不再消费这些字段；INS校准仍使用其开控状态和源时间。`Robot_ReportArmState()`在同一临界区覆盖诊断并撤销底盘命令，保留Arm闭环/发送后故障的同周期停机。

差速、斜坡、两轮PI、反馈超时及旧帧取消均已实现，参数和实物性能仍待验。功率计已接CAN2标准`0x31`、DLC4，小端有符号int16×0.1 W/J；首版有保守限幅和低能量/反馈超时的有时限停车，不承诺严格瞬态50 W保证。调参入口及功率边界分别见README_CHASSIS、README_VEHICLE。

| `1Bsp/dr16_bsp.c/.h` | 完整18字节DBUS解码和输入验证、DMA+空闲中断、双缓冲及接收状态 |
| `2User_Driver` | 实物通道/正向、死区、超时、夹爪占位参数 |
| `2User_Driver` | V2.1 映射、待机、停车回中和姿态许可 |
| `3Task` | 单板接口、保护连接、目标提交与状态快照 |
| `3Task` | 默认失能、保护原因汇总与重新开控锁存 |
| `2User_Driver`、`yaw_config.h` | 四轴与 yaw 分开维护参数，聚合为统一 CAN1 五轴配置 |

默认仍保留 `hardware_confirmed=false`、`pitch.mapping_confirmed=false`、遥控 `mapping_confirmed=false`。刷入默认固件后不会使能电机，不应把“已经编译通过”当作可直接带载操作。

1. 保持默认失能并支撑机械臂，观察 `DR16_GetStatus()` 的四轴/两拨杆原码、有效帧和错误计数；核对暂定 ch0=右横、ch1=右竖、ch2=左横、ch3=左竖及拨杆索引。USART3 RX PC11，线上 100000 baud、8 数据位+偶校验+1 停止位；F4 HAL 配置为 `9B + EVEN`。
2. 按 `README_ARM.md` 核对电机 ID、模式、DM 量程和反馈、机械传动、方向、零位、限位及负载参数，再有依据地更新三处确认门槛。方向先从反馈和低输出验证，不能只凭 CAD 或相向安装猜测。
3. 支撑并手动摆好约定零位，静止且反馈在线后调用 `Arm_CaptureZero()` 或调试命令 2，读取执行结果。两 pitch 同时校零（mask `0x06`）；整车需五轴均校零。重启或多圈位置失效后需重校，CAD 150°偏置不是软件零位。
4. 让底盘/安全管理持续提供真实停车与姿态许可。行驶或夹取模式下，停稳、四摇杆和右拨杆回中后，明确调用一次 `Robot_RequestControl()`；待机中不会开控。返回 1 只代表请求接收，仍须检查实际状态。
5. 在有支撑、低输出和小角度条件下验证方向、跟踪误差、抖动、饱和与温升，再逐步整定 PID 和速度/加速度。两 pitch 成对运行；完整遥控协调层按五轴开控，不能另起任务争写 `Arm_SetTargets()`。
6. 验证行驶左横 yaw/右横底盘请求互不串扰、夹取映射、切模式停稳回中、快档许可、待机保持和不自动使能；随后验证显式关控、关闭遥控器、互锁失联、反馈故障及恢复后不自动开控。
7. 单独验证电机侧通信超时和真实负载的下垂/制动行为。主控卡死或物理断线时，本机软件无法保证停机帧送达。底盘软件已接入，接口测试仍不能代替实际停车验收。

机械臂还需确认的问题、候选保持策略和参数清单见 `README_ARM.md`。
