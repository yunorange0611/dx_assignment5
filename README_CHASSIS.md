# 两轮底盘：分批实现与悬空调试

第一批：速度API为`0x0203`，纵向字段`longitudinal_speed_request`，取值[-1,1]，回中映射零速度，再经加减速斜坡。原加速度字段已删除，所有调用方须重新编译。右横转向仍为逆时针正，倒车不翻转；无Yaw跟随。

CAN1为机械臂/Yaw；CAN2为两台M3508/C620和功率计。CAN2两轮先占ID1/2、反馈0x201/0x202、共用0x200第一/二槽；左右和方向均须实测。功率计标准帧0x31、DLC4，功率与缓冲为有符号小端int16×0.1W/J，保留首帧及源时间。第三批已接保守功率限幅和低能量/功率反馈超时的受控停车，完整边界见README_VEHICLE.md；严格瞬态50W保证与实测停车距离仍未验收。

## 构建与默认边界

| 配置 | 用途 |
|---|---|
| Debug / Release / BenchDebug | 原四轴台架；不启动底盘任务，不发Yaw |
| VehicleDebug / VehicleRelease | 整车真实互锁/IMU/功率停车链；各实测确认及在线Yaw限位未就绪时禁止行驶 |
| ChassisBenchDebug | 显式悬空测试；四轴核心维持关闭，CAN2唯一任务发短脉冲 |
| YawBenchDebug | 原五轴owner内仅Yaw短时调参；不启动底盘与整车安全任务 |
| DmIdConfig | 独立配ID，不启动底盘 |

默认`ChassisConfig.hardware_confirmed=false`，遥控映射确认也为false；不会因编译成功自动开轮。先核对电调ID、方向、齿比、悬空固定与摇杆/拨杆原码，再据实设置确认标记。方向通过低电流短时试验确认，不先接反向反馈的闭环。

## 悬空入口

构建`ChassisBenchDebug`，使用同目录的固件与ELF。保持两轮悬空、机构有支撑，机械臂失能；左拨杆上（四轴关控）、右拨杆中、四杆回中。RC有效且新鲜、原owner持续更新、两轮首帧/温度/静止/反馈健康，才接受请求。不伪造整车互锁，不通过别的任务发CAN。

读取`g_chassis_status`和`g_chassis_debug_status`；外部仅写`g_chassis_debug_request`，字段写完后最后递增`request_seq`。这是调参命令而非持久开控。

| 字段 | 填写 |
|---|---|
| mode | 0停止、1清本地故障、2电流脉冲、3轮速脉冲 |
| wheel | 0左、1右，实际归属先核对 |
| value | 电流mA或转子rpm，绝对值不超过300，先从更小值开始 |
| duration_ms | 1..500ms，先短脉冲 |
| suspended_confirm | 0x53555350，人工确认已悬空，不是传感器检测 |
| request_seq | 最后写，和上次不同才消费 |

请求未就绪立即消费拒绝，不等待以后自动启；忙时新请求不续时；超时、移杆/拨杆、RC失联、全局显式关控、源停更或总线异常均取消当前脉冲。清故障只清本地锁存，不开控；恢复后须新的请求。非选轮电流槽位为零。关控/撤力不是机械锁止，低速测试结束后可能存在惯性滑转。

单轮方向通过后先Ki=0调速度P，再少量加I。速度脉冲复用同一个轮速PI，最终电流限制为min(300mA,配置上限)。调参不使用旧DJI对象，不另建输出任务。正常轮速PI以最终提交电流约束积分，队列失败转故障；入队成功不等于电机已执行。

底盘故障只由本地取消CAN2旧帧，CAN1由原owner按统一策略处理。两轮低速持续确认只表示驱动轮静止，不能证明坡道/抱死滑移时整车静止。

实物验收需逐轮记录正/负方向、目标/实际rpm、输出、反馈年龄、超时撤力及恢复步骤。软件测试不能替代这项验收；未烧录/未做悬空试验时明确记录为待验。
